# Migrating to v0.5.0

v0.5.0 adds two lifecycle actions, `reject` and `override`, publishes
conformance files for consumers in other languages, and adds the MIT LICENSE
file that `pyproject.toml` already declared. `SCHEMA_VERSION` stays 4 and the
signing payload stays version 4: no stored record needs migrating, and every
existing signature still verifies.

## What changed

- **`reject` action.** `proposition → demoted` is now legal, and only through
  `reject`. Use it when automated verification or a reviewer rejects a
  proposition before it was ever promoted. A rejected proposition sits in
  `demoted`, the same status a demoted axiom has; the action in its history
  says why. Like any `demoted` proposition it may later be promoted by a new
  signed transition or superseded.
- **`override` action.** Between `promoted` and `demoted`, in either direction,
  an authorized person may sign `override` instead of `demote` or `promote`.
  The status change is identical; the action records that a person overturned
  an automated status. `override` is not legal from `proposition` (an
  unreviewed proposition is promoted by `promote` or rejected by `reject`) or
  into or out of `superseded`.
- **Reasons are required.** `reject` and `override` transitions must carry a
  non-blank `reason`. The signer (`actor_did`) is the recorded author, and the
  action and reason are covered by the signature, so a signed `demote` cannot
  be relabelled as an `override` afterward.
- **`AXIOM_TRANSITION_ACTIONS`** (new). Read-only map from each legal
  `(from_status, to_status)` pair to the frozenset of actions legal for it.
  This is now the legality table that `AxiomTransition`, `AxiomTransitionDraft`
  and `apply_transition` check.
- **`AXIOM_TRANSITIONS`** keeps its shape (one action per pair) and now means
  "the default action for each pair". It gains
  `("proposition", "demoted"): "reject"`.
- **`REASON_REQUIRED_ACTIONS`** (new). `frozenset({reject, override})`.
- **Conformance files.** `conformance/identity-vectors.json`,
  `conformance/proposition.schema.json`, and
  `conformance/document-record.schema.json`, generated by
  `scripts/generate_conformance.py`. See [conformance](conformance.md).
- **JSON Schema for `content_iri`.** The generated schema now publishes the
  `content_iri` pattern. Python validation is unchanged.
- **LICENSE.** The MIT license text is now in the repository and the wheel.

## Compatibility

- Readers on v0.4.0 cannot parse a record whose history contains `reject` or
  `override`: the enum value is unknown to them. Upgrade every reader before a
  writer starts signing either action.
- Code that iterates `AXIOM_TRANSITIONS` to decide legality still works for
  every v0.4.0 transition, but misses `override`. Check
  `AXIOM_TRANSITION_ACTIONS` instead.
- Code that expected `proposition → demoted` to be illegal must now expect it
  to be legal through `reject` only.

## Signing a reject or override

```python
draft = AxiomTransitionDraft(
    sequence=len(proposition.axiom_history),
    from_status="promoted",
    to_status="demoted",
    action="override",
    actor_did=overseer_did,
    at=datetime.now(UTC),
    reason="Audit sample 12: the rule misreads subdivision 3",
)
transition = sign_transition(
    proposition.id, proposition.content_iri, draft, private_key, key_id
)
demoted = apply_transition(proposition, transition, DidKeyEd25519Verifier())
```

`did:key` remains self-certifying. Who may sign `override` (or `reject`) is the
consumer's policy: check `actor_did` against your own authorized overseers.
